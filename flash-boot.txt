flame mainline boot image - how to flash
=========================================

Artifact: flame-mainline-final.img
  Android boot image header v4, os_version Android 17 (matching the ROM's own
  boot.img), page 4096, empty header cmdline - field for field like the ROM's
  image, so first stage sees the header it expects. Two sections:

    kernel   the mainline arm64 Image plus sm4450-xiaomi-flame.dtb plus the EL1
             handover shim, built in that run. The shim takes the DTB the
             bootloader built from the vendor tree out of x0 and puts our board
             DTB there instead; see tools/shim.S and docs/mainline-port.md.
    ramdisk  the ROM's own generic ramdisk, 2600656 bytes, which is where this
             ROM keeps /init. CI cannot build it and must not copy it from a
             public place, so the job fetches it from the private
             i7m7r8/flame-stock repo, checks its sha256 against
             config/stock-ramdisk.sha256 in this repo, and attaches it with
             tools/attach_rom_ramdisk.py. RAMDISK.txt says which hash went in.

  flame-mainline-boot.img in the same artifact is the kernel with no ramdisk.
  It is the input to that step, not something to flash: the ROM's vendor_boot
  carries no /init either, so booting it gets a kernel that unpacks a rootfs
  with no init and resets in a few seconds.

Nothing else is replaced: vendor_boot, dtbo, vbmeta, super and the bootloader
partitions keep the ROM's own content.

1. Find the slot the ROM lives in, from a working Android shell:

     adb shell getprop ro.boot.slot_suffix        # _a or _b

   or from fastboot:

     fastboot get_staged_frac; fastboot getvar active-slot   # builds that answer

2. Back up what is there now (this is the whole restore procedure):

     adb shell "su -c 'cp /dev/block/by-name/boot$(getprop ro.boot.slot_suffix) /sdcard/boot-stock.img'"

   stock/boot.img in the ROM package is byte-identical, so the ROM zip alone is
   also a valid restore.

3. Flash once, and only to that slot:

     fastboot flash boot_a flame-mainline-final.img     # if suffix is _a
     fastboot flash boot_b flame-mainline-final.img     # if suffix is _b
     fastboot --set-active=<same slot>
     fastboot reboot

4. If it does not come up, hold Power+VolDown until fastboot and restore:

     fastboot flash boot_<slot> stock/boot.img
     fastboot reboot

   The image either boots or sits in the shim's halt loop; it cannot write to
   anything but the boot slot it was flashed to, so there is no state to undo.
   See BOOT-SAFETY.txt.

5. Optional, do this instead of step 3 if your ROM is not the build the private
   repo holds, or if you would rather not take a runner's word for its bytes.
   Attach the first stage from your own phone, which needs nothing but python3
   and your backup from step 2:

     python3 tools/attach_rom_ramdisk.py --boot flame-mainline-boot.img \
             --rom-boot boot-stock.img -o flame-mainline-my-slot.img

   The tool re-reads what it wrote and stops unless the kernel and ramdisk
   sections are byte-identical to the inputs, so a mismatched ROM revision
   shows up here rather than on the phone.

6. If it boots to a reset in a few seconds instead of to Android, the reason is
   on the oops partition by the time you are back in the stock ROM (pstore on
   block, recorded for panic AND for the reboot(2) that a giving-up init calls):

     su 0 dd if=/dev/block/by-name/oops bs=1M count=1 2>/dev/null | strings | tail -300

   Paste that; it is the boot log. Nothing else on the device survives this
   boot, so there is no second place to look.

   pstore writes to whatever PARTLABEL the config names, and "oops" is the name
   this build assumes. If that dd reads nothing, send the real partition list
   and the size of the candidates, and the next build points at one of them:

     ls /dev/block/by-name/ | tr '\n' ' '; echo
     for p in oops dump logfs; do echo -n "$p: "; blockdev --getsize64 /dev/block/by-name/$p 2>/dev/null || echo absent; done

   A wrong label is not a boot problem: pstore_blk is configured best_effort, so
   a missing partition means no log and nothing else changes.

First board bring-up is much easier with a console: the debug UART is the GenI
QUP at 0xa88000, 115200 8N1, and the bootargs in the DTB ask for it. Pinout and
level notes are in docs/hardware-flame.md.
