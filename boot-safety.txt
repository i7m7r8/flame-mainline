flame mainline boot - safety notes
==================================

Scope of every write: the boot partition of the slot that already holds
Infinity X Android 17, and nothing else.

  boot_<slot>     flame-mainline-boot.img   (mainline Image + flame DTB + shim)

Never flashed, ever: abl, xbl, xbl_config, tz, hyp, devcfg, pmic, qupfw, aop,
loaders, vbmeta, vbmeta_system, vendor_boot, dtbo, super, bootable recovery.
vendor_boot, dtbo and super keep the ROM's own content, so init still finds the
ROM's vendor ramdisk, DTBO, DLKMs, and the ROM's own AVB chain.

Why this cannot brick the device:
  - the Qualcomm loader partitions are the only thing that can be destroyed by
    a bad flash, and they are never written;
  - our boot image has no AVB hash descriptor of its own, so vbmeta still
    describes the ROM's boot image - if that mismatch is a problem the ROM
    simply does not boot, and flashing stock boot.img fixes it;
  - the payload never writes to flash. If the shim ever gets confused it halts
    in a `b .` loop with interrupts on, which is recoverable by holding
    Power+VolDown until fastboot comes back.

Restore, either of:
  1. recovery (the ROM's own, in its own partition, unmodified):
     install the Infinity X zip, or just its boot.img
  2. fastboot:
     fastboot flash boot_<slot> stock/boot.img      # byte-identical copy
     fastboot reboot

Back up the slot before flashing, from a root shell:
  cp /dev/block/by-name/boot$(getprop ro.boot.slot_suffix) /sdcard/boot-stock.img

Two things are worth remembering about the earlier plan. Slot b used to hold
Debian 13; that route was dropped, and the "never touch *_a" rule that came with
it no longer applies - what applies now is "only boot_<slot the ROM lives in>".
And the image is slot-agnostic on purpose: the handover shim hands the
bootloader's own device tree to the kernel, whose bootargs carry
androidboot.slot_suffix, so the same image works whichever slot it is flashed
to.
